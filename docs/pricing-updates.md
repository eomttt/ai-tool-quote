# 가격 갱신 설계

## 첫 버전

현재 구현은 `tools.json`과 `pricing.json`을 읽고 Zod로 검증한 뒤 앱에 포함합니다. 사용자가 조건을 바꾸면 비용 계산은 즉시 바뀌지만, 공급자의 가격을 실시간으로 가져오지는 않습니다.

서비스·요금제·모델 소모량을 구분합니다. 같은 모델을 여러 서비스가 제공해도 서비스별 크레딧 가치는 서로 바꿔 쓰지 않습니다.
현재는 Git 이력이 가격 변경 이력을 보존합니다.

## 자동 수집을 붙이는 순서

1. 공식 요금표를 하루 한 번 수집하는 서버 작업을 만듭니다. 공식 가격 API가 있으면 먼저 사용하고, 공개 페이지는 제공자의 접근 조건을 지켜 확인합니다.
2. 이전 원문과 비교해 바뀐 가격·크레딧·제한만 검토 대기 상태로 저장합니다. 요금제와 모델별 소모량이 서로 맞는지 검증합니다.
3. 검토한 버전만 공개 견적 데이터로 승격합니다. 사이트는 마지막 검토 완료 버전을 캐시해서 읽습니다.

요금 변경이 자주 발생하는 핵심 도구는 6시간 간격으로 확인하고, 후보 도구는 주 1회 확인하는 식으로 빈도를 나눌 수 있습니다.
이는 초기 운영 제안이며 실제 갱신 보장 시간이 아닙니다.

## 수집 시각과 검토 시각

| 필드                 | 의미                            | 변경 시점          |
| -------------------- | ------------------------------- | ------------------ |
| `fetchedAt`          | 공식 원문을 가져온 시각         | 수집 성공          |
| `reviewedAt`         | 요금 의미를 확인한 시각         | 검토 완료          |
| `effectiveAt`        | 공급자가 밝힌 적용 시각         | 명시된 경우만 기록 |
| `sourceUrl`          | 가격과 규칙의 공식 근거         | 출처 변경          |
| `region`, `currency` | 가격이 적용되는 지역과 통화     | 요금 범위 변경     |
| `status`             | 검토 대기·공개·오래됨·수집 실패 | 처리 단계 변경     |

현재의 `checkedAt`은 `reviewedAt`에 해당합니다. 자동 수집 단계에서 위 필드를 가진 저장소로 옮깁니다.
페이지를 가져온 날짜를 가격 확인일로 표시하면 안 됩니다.

## 변경 검토 기준

- 월 결제와 연간 결제의 월 환산액을 분리하고 실제 청구액을 저장합니다.
- 포함 크레딧, 무료 지급의 일회성 여부, 소멸·이월, 추가 팩 단위를 확인합니다.
- 모델·출력 해상도·길이·음성 포함 여부·생성당 소모량을 함께 검증합니다.
- 할인 종료일, 신규 가입 제한, 지역, 상업 이용 조건이 빠지면 검토 대기에 둡니다.
- 원문 안의 지시문을 수집 작업의 명령으로 실행하지 않습니다. AI를 쓰더라도 원문에서 필드를 추출하는 역할로 제한합니다.

파싱 실패나 로그인 요구가 생기면 빈값·0원으로 덮어쓰지 않습니다.
마지막 검토본과 확인일을 유지하다가 유효기간을 넘으면 금액 견적을 중단합니다.
정상 수집만 확인하고 검토 없이 자동 공개하는 방식은 초기에는 사용하지 않습니다.

## 공개 사이트로 확장할 때

서버의 공개 가격 API 또는 검토된 JSON을 React가 읽게 하면 가격 변경마다 사이트를 다시 빌드하지 않아도 됩니다.
공개 데이터에는 가격과 출처만 포함하고 수집용 키·로그인 정보는 서버에 남깁니다.
관리자 검토 화면, 변경 이력, 실패 알림은 그다음 구현 범위입니다.
