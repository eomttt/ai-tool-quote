# 상황 검색과 제품 메타데이터

사용자는 도구 이름을 몰라도 가진 재료와 만들고 싶은 결과를 문장으로 적습니다. 검색은 영상·이미지 38개 도구 전체를 대상으로 하며, 추천 카드에는 각 도구가 맡을 수 있는 작업을 표시합니다. 도구 하나가 입력한 상황 전체를 해결한다고 보장하지 않습니다.

## 공식 사실과 활용 예시

`src/domains/catalog/data/product-profiles.json`이 검색과 화면에 쓰는 제품 기능의 원본입니다. 2026년 9월 21일 공식 제품 소개와 도움말에서 38개 도구의 53개 기능을 요약했습니다. 이는 현재 카탈로그의 영상·이미지 범위에 대한 검토이며, 각 서비스의 모든 기능을 조사했다는 뜻은 아닙니다.

프로필은 도구 ID, 검토 시각, 출처 목록, 기능 목록으로 구성합니다. 기능에는 다음을 기록합니다.

- `medium`: 결과물의 영상·이미지 구분
- `summary`: 기능 설명의 한국어·영어 요약
- `inputs`, `outputs`: 사용자가 준비하는 재료와 만드는 결과물
- `sourceId`: 근거가 되는 공식 제품 소개나 도움말
- `evidenceExcerpt`: 저장한 본문에서 해당 기능을 다시 찾을 수 있는 짧은 발췌

출처에는 URL, 제목, 확인일, 수집 방법, 근거 파일 경로가 있습니다. 원문 수집 시각과 기능 검토 시각은 별도입니다. HTTP 200 응답이나 수집 성공만으로 기능을 검증했다고 표시하지 않습니다. `evidenceExcerpt`는 근거 위치를 찾는 용도이며, 요약 전체의 의미는 링크한 본문을 읽어 검토합니다.

`scenarios.json`은 편집자가 연결한 활용 예시입니다. `basis: editorial`과 `evidence`에 연결한 도구·기능 ID를 명시합니다. 예를 들어 Photoroom의 공식 기능은 상품 사진의 배경 생성·제거이고, ‘집에서 찍은 상품 사진을 쇼핑몰에 올리기’는 이를 활용하는 상황입니다. 플랫폼에 자동 업로드하거나 매출을 보장한다는 뜻은 아닙니다.

`tools.json`에는 서비스 식별 정보, 아이콘, 분류와 기존 편집 안내가 남아 있습니다. 화면의 기능 설명은 제품 프로필이 우선하며, 기존 일반 설명·태그를 검색 근거로 사용하지 않습니다. `bestFor`와 선택 시 고려 사항은 편집 안내입니다. 요금은 별도의 `pricing.json`과 `pricing-audits.json`으로 관리합니다.

## 수집과 검토

```sh
npm run crawl:products
npm run crawl:products -- --tool photoroom
npm run crawl:products -- --tool photoroom --url https://www.photoroom.com/
npm run test:pricing-sources
```

`research/product-sources.json`의 공식 URL을 요청하고 `research/products/<수집 시각>/`에 추출 본문·해시·수집 결과를 저장합니다. 원본 HTML은 Git에서 제외한 `.cache/product-sources/`에 보관합니다. 수집 오류도 기록하며, 공개 JSON을 자동 변경하지 않습니다. 주기적인 실행은 설정하지 않았습니다.

홈페이지에 설명이 부족하면 공식 기능 문서나 도움말을 사용합니다. 이번 검토에서 Canva와 NightCafe의 직접 HTTP 수집은 실패해 공식 도움말을 웹 검색 도구로 읽었습니다. 해당 기록은 `research/products/manual-2026-09-21/`에 방법과 발췌를 남겼습니다. 두 기록을 HTTP 크롤링 성공으로 표시하지 않습니다.

갱신 시에는 이전 본문과의 차이, 실제 입력·출력 지원, 기능의 모델·요금제 조건을 읽고 프로필을 수정합니다. 이어서 활용 상황 연결을 검토하고 `catalog.en.json`의 요약 번역을 맞춥니다. 새 도구나 새 제작 분야는 근거가 있는 기능을 등록해야 검증을 통과합니다.

## 검색 방식

BM25F로 도구 이름·별칭, 편집한 상황, 공식 기능·입력·출력 필드를 검색합니다. 한·영 동의어와 자주 쓰는 표현은 `search-vocabulary.json`에서 관리합니다. 한국어 조사를 일부 정리하지만 완전한 형태소 분석은 아닙니다.

필드별 단어 빈도를 길이로 보정하고 가중치를 합친 뒤 한 번 포화시킵니다. 희소 단어에 더 높은 점수를 주며 결과는 관련도순으로 표시합니다. 이름·별칭을 정확히 입력하면 그 이름에 해당하는 서비스를 우선합니다. 같은 모델 별칭을 가진 서비스는 모두 남깁니다.

이 방식은 단어와 동의어를 대조하는 검색입니다. 부정 표현, 예산, 상업적 이용 조건 등 문장의 모든 제약을 판정하지 않습니다. 낮은 점수를 확신도나 성공 확률로 표시하지 않으며, 광고비는 순위에 사용하지 않습니다. 새 상황을 추가할 때는 실제 문장과 기대하는 도구를 검색 테스트에 추가해 결과를 확인합니다.
